Round two: protocol first, then askNew conversation. Protocol and question are already combined; copy once.
When checking references, follow this protocol:
1. Never conclude from memory. Any entry whose original record you have not retrieved is marked UNVERIFIED; never call it "correct".
2. Check every field of each entry: authors and their order, title, journal, volume, first page or article number, year.
3. For each field, state the evidence: which database you queried and what the record says.
4. A DOI that resolves is not a pass; confirm that what it opens is this very paper.
5. When something does not match, state what the entry says and what the record says; do not "correct" it yourself.
6. End with a table: entry number, verdict (correct / wrong / UNVERIFIED), evidence.

2. Live demo: one sentence, from optical potential to experimental data

This is the sentence I ran live with Claude Code plus the FUSION skills. You can also paste it as is into a web AI and compare what each hands back.

The live-demo sentenceSend after starting the agent in an empty folder
Use the KD02 optical potential to compute the elastic-scattering angular distribution (ratio to Rutherford) for p + 208Pb at 30 MeV, and plot it together with the experimental data from EXFOR in one figure, using Python, saved as results/p208pb_30MeV.png. Tell me which experimental data set you used and which checks you did.

FUSION skills: github.com/jinleiphys/FUSION. It also runs without the skills; see what is missing.

4. Read a new paper, find a collaboration

Download a paper from arXiv into a paper/ directory, then start the agent in that directory. Replace "personal wiki" with your own notes or publication list.

New paper + two wikisIts guesses and collaboration ideas are guesses; you judge whether they hold up
paper/ contains a paper I just downloaded from arXiv. First read it, then search the arXiv wiki for this group's earlier papers, summarize what they have been working on, guess what they might do next, and list the papers that support each guess. Then search my personal wiki, using only my published papers and public code, and find problems we could work on together. Give a source for every point (arXiv number or my paper).

5. One comparison to try at home

Pick a code you use often and ask the same sentence twice: once giving nothing; once after giving it a verified input and a known result. Compare what comes back.
