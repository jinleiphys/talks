# B8 预注册：跨模型审计的缺陷检出率

**冻结时间** 2026-07-20，扫描开始之前
**目的** 把稿件中"跨模型交叉验证"从规范性口号变成可核查的测量
**关键约束** 分母是全部合格审计事件，不是成功案例集合。只报成功案例即为选择性报告，本测量作废。

---

## 1. 总体（分母）

**合格审计事件**定义为：在 `~/research-wiki-personal/` 与 `~/research-wiki/` 中有记录的、一次针对具体研究产物（手稿、代码、数值结果、引用）的跨模型检查，且该检查的发起早于本篇《核技术》稿件（2026-07-17 首次成稿）。

**必须计入分母的情形，无论结果如何：**
- 检查判定 PASS / 未发现问题
- 检查提出了意见但事后证明是错的或被否决
- 检查提出了意见但无法追溯到任何可核查改动
- 检查记录只有叙述性总结，没有锚点

**不计入总体：**
- 单模型自查（无第二模型参与）
- 2026-07-17 之后、为本文而做的任何检查（事后构造，禁止）
- 与研究产物无关的检查（如排版、日程）

## 2. 纳入为"客观缺陷检出"的判据

一个事件计为**客观检出**，当且仅当它同时满足：

(a) 检查方指出了一个具体缺陷（不是"建议润色"这类无真值的意见）；且
(b) 该缺陷导致了一处**独立可核查**的改动，锚点至少为下列之一：
   - 一个 commit hash
   - 一个数据产物文件（如 certification / benchmark JSON）
   - 一个可复现的数值修正（改动前后的数字都有记录）
   - 一次 DOI / 文献元数据的核验结果
   - 一个基准比较数字

只满足 (a) 不满足 (b) 的，计为**叙述性事件**，进分母不进分子。

## 3. 缺陷分类（预先定义，扫描后不得新增类别）

- C1 数值收敛 / 精度
- C2 代码缺陷
- C3 引用 / 元数据错误
- C4 物理表述与恒等性（措辞超出计算所支持的范围）
- C5 数据/图表与正文不一致
- C0 未发现缺陷（PASS）

扫描中若出现无法归入 C0-C5 的客观缺陷，记为 C9-其他并在报告中单列，**不得回头改动上述定义**。

## 4. 保密排除规则（扫描前生效）

硬排除，不进入任何统计与任何公开表格：
- `reviews/` 全目录（审稿与编辑材料，永久保密）
- 任何 `*.private.md`
- 未发表手稿中尚未公开的具体结论、数据、referee 身份
- 合作者通信内容

**公开报告只出聚合计数与已发表工作对应的示例。** 涉及在投稿件的事件可计入分母，但示例描述须限制在已公开信息（如已在 arXiv 的版本）范围内。

## 5. 预先声明的失败条件

- 若客观检出事件 < 3，结论为"跨模型验证在本部署中缺乏可核查证据"，稿件中相关表述**降级为工作规则而非有效性主张**，不写成结果节。
- 若无法可靠重建分母（合格事件总数不可数），本测量作废，不进稿件。

## 6. 预先声明的解释边界

即使结果为正，本测量**只**支持"跨模型审计能检出可核查缺陷"这一条，**不**支持：
- 五层架构整体有效
- 效率提升
- 研究质量提升
- 智能体具备判断力

样本为单一研究者的单一部署（n=1 部署，事件级 n>1），无对照组。报告中必须写明。
