## 页面（22 页正文 + 备用）

### 一、什么是 agent（0:00-8:00）

1. 封面：《核物理需要什么样的 agent》，副题"它得带着文献，会用我们的程序，还得能证明自己没算错"。
2. chatbot 和 agent 的区别：chatbot 是你问它答，一轮一轮，输出是文字。agent 是把模型放进一个循环：读任务，决定调用哪个工具（读文件、跑命令、搜索），看工具返回，再决定下一步，直到做完。四个部件：模型（推理）、工具（手）、上下文（它能看到的文件和文档）、循环（自己走多步）。
3. 这件事在软件界已经发生了：编程 agent 能在一个仓库里读代码、改代码、跑测试、修错，一次几十步。我这一年怎么用它：写代码、查文献、审稿前自查，一个模型提方案，另一个模型来挑错。
4. 全场论点：agent 的能力 = 模型 × 它手边的工具和知识。模型几个月换一代，租来的；工具和领域知识是我们自己能写的。"技能"就是一份 Markdown 文档，告诉 agent 在某类任务上该怎么做，它需要时读取。

### 二、核物理的 agent 长什么样（8:00-16:00）

5. 核理论一天的活拆开：读文献、找实验数据、装程序、写输入卡、跑、判断结果对不对、写论文。哪些是物理，哪些是体力。只有"判断"是物理。
6. 通用 agent 去干会怎样：以 FRESCO 为例，它按全局光学势的习惯理解半径约定，漏掉一行 ap=0，核子入射时每个半径偏大约 22%，程序正常结束，图也好看。还会编不存在的引用。三个根子：知识来自训练语料，不可审；没有基准，无法判断这次输出可不可信；错误不积累修正。
7. 我心里的核物理 agent，三样东西：它带着文献（六万篇本地，可核对）；它会用我们的程序（每个程序一份写下来的专家经验：怎么装、输入卡里的坑、拿什么已知结果对、容差多少）；它记得你做过什么（你的论文、合作者、踩过的坑，写在一个它每次都读的档案里）。
8. FUSION 一页总览：两层（文献层 61,167 页；技能层 26 份，其中 20 份驱动具体程序）；不绑定 agent，不绑定模型（opencode / Claude Code / Codex 都能加载；DeepSeek、Qwen、GLM 都能跑）；MIT；github.com/jinleiphys/FUSION。

### 三、文献：它能帮你做什么（16:00-24:00）

9. 六万篇是怎么组织的：61,059 篇 arXiv nucl-th，一篇一页（摘要 + 全文摘要：主张、方法、关键数字、上下文），108 个 PhySH 主题页，70 万条语料内引用边，23 万条带类型的引用关系（uses / compares / extends / contrasts / applies）。纯 Markdown 和 TSV，grep 读，无服务器，无 API key，无网络。
10. 语料地图（figures/corpus-map.png）：55,850 篇论文的引用投影，地形是密度，地名取自 PhySH 主题。
11. 演示 1（4-5 分钟）：只给一篇 PDF（Abu-Ibrahim 等，PRC 77, 034607），离线定位到 0710.4193，引用网络给出它引的 8 篇和引它的 5 篇，摘要里带可核对的数字 p+12C 40 MeV σ_R = 432 mb。
12. 边界：页面是机器生成的摘要，会错，引论文不引页面；引用边只在语料内统计，RIKEN 的实验论文不在 nucl-th，被引数被低估。

### 四、程序：它能帮你做什么（24:00-34:00）

13. 一份技能长什么样：FRESCO SKILL.md 原文节选（"Never report a FRESCO number you have not verified"；"Start from a verified example, do not hand-write a deck from memory"；半径约定那一段；anchor 表格里 B1-elastic 1575.17495 vs 1575.17481，7 位）。
14. 覆盖了哪些程序：反应/光学模型 FRESCO(+SFRESCO)、COLOSS、CCFULL、pikoe、NLAT、CNOK、SIDES、SWANLOP；结构/从头算 GSM、KSHELL、NuclearToolkit.jl、Sky3D；裂变/统计 CGMF、TALYS；核天体/R 矩阵 AZURE2、SkyNet；重离子/状态方程 SMASH、GiBUU、Thermal-FIST、vHLLE；实验数据 EXFOR。
15. 演示 2（4-5 分钟）：一句话"算 50 MeV 的 n+90Zr 弹性散射，用 KD02 全局光学势，然后跟 EXFOR 上有的实验数据比一下"。四个要看的节点：参数取自本地 Koning 原始 kd02.f；它写出 ap=0；做步长与分波数收敛检查；查 EXFOR 然后报告 50 MeV 没有数据。
16. 凭什么信它，一页：Tier 1 14 份（程序自带参考值，几份逐位相同）/ Tier 2 6 份（用跨平台、物理恒等式或解析解钉住，vHLLE 对 Gubser 流）；双平台 macOS/ARM + Linux/x86；第二个求解器互检（n+90Zr 50 MeV：COLOSS 1299.188 mb，FRESCO 1299.191 mb，6 位一致，两者结构上毫无关系）；发布前另一个 AI 拆台，抓到过 TALYS 脚本跑旧输入卡然后报告成功。
17. 基准证明的是这次构建复现了一个已知结果，它不证明你的计算是对的。选哪个光学势、怎么切连续态、能量范围合不合适，还是你的事。物理仍然是你的。

### 五、这对研究方式意味着什么（34:00-42:00）

18. 知识放在哪里：过去在课题组口传，一个人毕业就没了；现在是仓库里的 Markdown，可读、可审、可 PR，一次发现的坑之后所有人受益。
19. 一天的工作会变成什么样：一个具体场景（早上给它一个物理问题，它查文献、跑两三个程序、互相对，你只做判断那一步）。
20. 现在还不行的地方：冷启动安装只有 FRESCO 从空缓存装起来验过；国内校园网 github 六次连接零成功，需要代理；TALYS 要 11 GB；Windows 没有构建；只有作者一个人用过。
21. 最想要的反馈：一个看起来对、但其实错的结果。其次装不上的程序、别扭的地方、你希望哪个程序也有一份技能。
22. 结尾：跑一个核物理程序最难的一步从来不是让它跑起来，是知道它跑对了。这件事以前靠口口相传，现在可以被写下来、被检查、被别人接着改。github.com/jinleiphys/FUSION · jinl@tongji.edu.cn
